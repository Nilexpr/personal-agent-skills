# Verification

## Fidelity

Reconcile the delivered explanation against source coverage. Check meanings, relationships, conditions, exceptions, units, and uncertainty. Confirm that the diagram, model rules, text, and feedback agree; identify unsupported parts explicitly.

## Behavior

Run representative interactions and meaningful alternatives in the actual delivery environment. Check changed inputs, branching outcomes, replay or reset where provided, synchronized explanations, and feedback export. Inspect keyboard use, narrow layouts, and reduced motion. Report checks that could not be performed.

## Understanding

Ask whether a learner can locate the relevant information, explain an observed change, and predict a meaningful variation using the declared prerequisites. Distinguish problems in the material or interface from gaps in understanding, and return unresolved issues to the learning workflow.

## Initial validation cases

The scaffold has not yet been validated through these cases:

- Task dependencies: completing one prerequisite leaves a task blocked when another remains; completing all prerequisites permits starting without implying completion.
- Continuous quantities: changing an input updates the represented quantity and explanation under explicit units, rules, and boundaries.
- Conceptual relationships: inspecting definitions and connections preserves qualifications without inventing executable or causal behavior.

Use these cases to revise the guidance before claiming demonstrated cross-domain teaching behavior.
