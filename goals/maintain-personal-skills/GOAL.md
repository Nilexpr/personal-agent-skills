# 维护个人 Skills 与 AGENTS.md

## Goal

持续开发和维护本仓库中可复用的个人 skills 与 AGENTS.md 规则。

## Why

为个人 skills 与 AGENTS.md 规则的维护建立简洁、准确且可持续维护的长期工作基础，使后续工作能够始终围绕已确认的范围、约束和判断标准推进。

## Constraints

本仓库由人工持续参与维护。目录、文件命名和文档应简单直接，充分考虑人类阅读和手动修改的便利；仅在确有必要时增加文件层级、工具和流程。

默认范围包括 `skills/` 内各 skill、`agentmd/` 内 AGENTS.md 规则源文件及本仓库 `AGENTS.md` 的新增、修改，以及配套文档、脚本和测试的维护与验证。安装、发布、跨 Agent 同步、Git 提交及远端操作仅在用户另行明确要求时纳入工作范围；项目外配置不作为默认维护对象。

依赖管理工具的目标、设计和实现由独立的 [依赖管理目标](../dependencies/GOAL.md)维护；structure 等 skill 的修订仍归本目标。

Skill 编写还应满足：

- 新建 skill 优先使用一个常用、含义明确的小写英文单词，选择能代表其核心用途的名称，避免为了满足单词形式而拼接词语或使用生僻缩写。
- 每个 skill 的正文文件尽量不超过 3 个，包括 `SKILL.md` 和配套说明，不计配置、脚本和素材；仅在不同工作流分支或明确职责需要时拆分。
- 完整、准确、清楚地表达必要含义优先于篇幅要求。在此前提下，以每个正文文件 600 个英文单词以内为精简目标，按文件全文以空白分隔统计。优先删除重复和无效说明，按职责与工作流需要决定拆分。
- 保持表达克制、精准，删除重复描述和不改变 Agent 行为的说明。
- 每个概念具有一个精确、清晰且稳定的定义；修改定义必须作为显式变更处理。
- 先实现最小、自包含、可运行的版本；仅根据实际使用中发现的问题增加规则。
- Skill 的文件产物承载需要长期保留的结果；结论与其形成依据一并保存，中间过程由当前任务承载。以跨任务传递当前状态为目的的 Skill 可以创建临时交接文件，例如 `handoff`。

## Satisfied when

这是一个持续目标，不设置整个项目的最终完成日期。每次增量工作在满足以下条件时视为完成：

- 已实现用户确认范围内的需求。
- skill 与 AGENTS.md 规则的说明和实际行为一致。
- 相关检查具有可复现的证据。
- 尚未解决的问题和限制已明确记录。
