# 维护个人 Agent Skills

## Goal

持续开发和维护本仓库中可复用的个人 Agent Skills。

## Why

为个人 skills 项目建立简洁、准确且可持续维护的长期工作基础，使后续工作能够始终围绕已确认的范围、约束和判断标准推进。

## Constraints

默认范围包括 `skills/` 内各 skill 的新增、修改、文档维护和验证。安装、发布、跨 Agent 同步、Git 提交及远端操作仅在用户另行明确要求时纳入工作范围；项目外配置不作为默认维护对象。

Skill 编写还应满足：

- 完整、准确地表达必要含义优先于体积限制；通常将每个 `SKILL.md` 控制在 60 行和 500 个英文单词以内，可以保持在 40 行以内时优先更小。
- 保持表达克制、精准，删除重复描述和不改变 Agent 行为的说明。
- 每个概念具有一个精确、清晰且稳定的定义；修改定义必须作为显式变更处理。
- 先实现最小、自包含、可运行的版本；仅根据实际使用中发现的问题增加规则。
- Skill 的文件产物承载需要长期保留的结果；结论与其形成依据一并保存，中间过程由当前任务承载。以跨任务传递当前状态为目的的 Skill 可以创建临时交接文件，例如 `handoff`。

## Satisfied when

这是一个持续目标，不设置整个项目的最终完成日期。每次增量工作在满足以下条件时视为完成：

- 已实现用户确认范围内的需求。
- skill 的说明与实际行为一致。
- 相关检查具有可复现的证据。
- 尚未解决的问题和限制已明确记录。
