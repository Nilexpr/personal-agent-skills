# 依赖管理工具

## Goal

提供一个供 LLM 主动调用的依赖管理工具，在每个工作目录内独立保存和查询显式依赖，使 LLM 能在文件变化后找到需要检查的依赖方，并自行判断影响及处理方式。

## Why

仅靠及时核验和更新的自然语言约定，仍可能遗漏与变更有关的资料。显式依赖为后续检查提供可查询的范围，并保留建立关联的依据。

## Constraints

- 工具仅管理工作目录内被 Git 索引跟踪的文件，分析工作区当前内容；已跟踪的未提交修改和已加入索引的新文件纳入，未跟踪文件排除。
- 首版只处理文件，设计须为后续扩展到段落、文件夹等粒度保留空间，不能将对象模型和查询接口永久限定为整文件。
- 支持同一工作目录内多个 LLM 会话并发修改依赖，避免相互覆盖。
- 保持工具简单；依赖由 LLM 显式维护，变化路径由 LLM 主动提供，具体影响和处理方式由 LLM 判断。
- 首版采用 Rust 同步 CLI 和 SQLite，提供依赖维护、查询与结构化错误反馈；对象、定位和依赖分别表示，数据库结构带版本。具体选择与依据见 [Decisions](DECISIONS.md)。

## Satisfied when

- CLI 在终端按工作目录内 Git 跟踪文件的实际路径展示目录树，完整保留没有关联的文件；支持查询每个文件依赖谁、谁依赖它，并列出没有任何已登记关系的文件，不提供页面。
- 支持已有工作目录的依赖初始化：工具提供完整 Git 跟踪清单和逐文件分析记录，LLM 分批分析、判断依赖并批量登记；新 session 可查询未分析及内容变化的文件继续处理。已分析但无关联的文件也计入覆盖；结果说明待核对关系，不将覆盖完成等同于已发现全部隐含依赖。
- 已实现确认范围内的依赖维护、直接查询、按需间接查询和异常反馈，结果可供 LLM 使用。
- 关键行为及并发修改具有可复现的验证证据。
- 对象表示与接口的扩展方式已经明确，能够说明未来如何加入段落或文件夹粒度，而无需重新登记全部既有依赖。
- 使用方式、识别边界和剩余限制已记录。
