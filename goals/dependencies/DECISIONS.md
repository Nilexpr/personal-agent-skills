# 依赖管理工具

- **管理范围由 Git 索引决定，文件内容读取工作区当前版本。**
  - Basis: 用户于 2026-10-10 确认排除本地参考资料，保留工具源码和目标记录，并批准实施。
  - Scope: 子目录取索引范围与工作目录的交集；新增和更新校验最终两个端点，删除允许清理旧关系；工具本身不执行 `git add`。

- **范围外关系必须显式清理，普通查询不沿范围外对象传播。**
  - Basis: 用户要求不静默删除，随后批准核对并清理参考资料关系。
  - Scope: 先提供只读范围清单，清理前保留可恢复数据；批量操作仍全部成功或全部回滚，提交前复核索引范围是否变化。

- **首版采用 Rust 同步 CLI，SQLite 保存依赖记录。**
  - Basis: 用户于 2026-10-10 在旁支会话确认并授权本地实施；使用 clap、rusqlite（bundled）、serde/serde_json，实现小型、自包含的工具。

- **提供简单 CLI，以终端目录树查看 Git 跟踪文件及关联情况。**
  - Basis: 用户于 2026-10-10 明确不需要页面，并批准 CLI 改造。
  - Scope: 目录树保留零关联文件，支持按关联和分析状态筛选；查询返回原因和路径，支持易读文本与 JSON。不加入页面、后台服务、变更历史、审计、详细 tracing、指标或缓存系统。

- **已有工作目录的初始依赖由 LLM 分析建立，不限于正文中的显式链接。**
  - Basis: 用户于 2026-10-09 提出应能从已有仓库创建初始关联，并明确选择“LLM 分析并建立初始依赖”。
  - Scope: LLM 阅读选定范围、判断依赖，工具负责批量登记；无法确认的关系列为待核对，并与已确认依赖区分。初始化不承诺发现所有隐含依赖，后续仍由 LLM 主动维护。

- **文件依赖由 LLM 显式建立和维护，每个工作目录独立管理，关联可附带简短原因。**
  - Basis: 用户于 2026-10-09 确认关联由 LLM 维护，工具负责保存和查询，并选择每个工作目录独立维护、允许补充关联原因。
  - Scope: 首版处理文件，不从 Markdown 正文自动提取关联；具体影响及更新方式交给 LLM 判断。关联持久化采用 SQLite，Git 共享与合并流程不纳入首版。

- **A 依赖 B 时，B 变化后应能查到 A；默认查询直接依赖方，按需展开间接依赖并保留关联路径。**
  - Basis: 用户于 2026-10-09 明确“依赖方需要能感知到被依赖方的变化”，并接受默认只查直接关联，避免无条件扩大待检查范围。

- **工具保存逐文件分析记录，按主动调用时的内容指纹核对覆盖。**
  - Basis: 用户于 2026-10-10 批准由工具维护初始化覆盖记录，供新 session 接续处理。
  - Scope: 区分未分析、当前内容已分析、内容变化需复核及无法读取；无关联独立统计。登记时核对内容指纹和分析记录版本，可与关系修改一起批量提交。工具不监控文件，依赖变更的具体影响仍由 LLM 主动查询和判断。

- **查询涉及已缺失的文件时，报告错误并返回已有依赖；登记新关联时文件不存在则拒绝写入。**
  - Basis: 用户于 2026-10-09 要求异常对 LLM 可见，随后确认上述缺失文件处理建议。
  - Scope: 不因文件缺失自动删除已有依赖，保留供 LLM 核对的线索。
