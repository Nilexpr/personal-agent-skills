# Workspace

- 使用 `structure` skill。

## 仓库与目录

- 开始工作前，确认任务涉及的仓库和实际工作目录，按任务需要读取项目规则；涉及多个仓库时，分别检查分支及未提交改动。
- 新建或迁移项目时，沿用工作区现有目录约定，并在项目内维护 README 和必要的项目规则。
- 工作目录缺失时，先核对实际路径、`.gitignore` 和 `git worktree list`，确认原因后再处理；不因某个 worktree 中缺少目录就重建或删除工程。

## 开发

- 以满足需求的最小改动为准，并独立验证修改部分。
- 除非无法安全实现需求，否则保持已有执行链路；新功能优先采用边界清晰、自包含的实现，减少新增依赖和集成点。

## 工具链

- 使用工具链公开支持的命令和流程，以项目实际版本的配置和文档为准。
- 用户明确指定命令时，在正确目录中原样执行；需要改变命令或参数时先说明原因并取得确认。
